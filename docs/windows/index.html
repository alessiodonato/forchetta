Forchetta on Windows

A beta that needs people to try it.

Version 0.13.0-beta.1, 23 November 2026. The tests pass on macOS and on Linux. It has not been tried on a Windows PC yet.

Forchetta runs its Claude Code sessions in tmux, which Windows doesn't have. So on Windows it runs inside WSL 2, the Linux that comes with it, next to Claude Code and your projects. You use it from a window of Edge or Chrome: the same page as on a Mac.

Before you start

  • It sees the sessions started inside WSL. Those of PowerShell, or of Claude Code for Windows, don't show up.
  • It adds hooks to ~/.claude/settings.json in WSL. It shows you every change, asks first, and keeps a copy of the file.
  • There is no app. No menu bar and no shortcut from any program: the window is one of Edge or Chrome.

Install

  1. WSL 2, if you don't have it. In PowerShell, as administrator

    wsl --install
    Then restart Windows and open Ubuntu from the Start menu: the next steps are in that terminal. If you have WSL already, wsl -l -v must say version 2, with Ubuntu 22.04 or later.

  2. Claude Code inside Ubuntu. The one of Windows isn't enough

    curl -fsSL https://claude.ai/install.sh | bash
    Run claude once and log in.

  3. What Forchetta needs: tmux and two small tools, from Ubuntu.

    sudo apt update && sudo apt install -y curl tmux lsof
    It asks for your password of Ubuntu. Nothing after this runs as root.

  4. Forchetta. On its own: at the end it asks you something

    curl -fsSLo ~/forchetta-install.sh https://github.com/alessiodonato/forchetta/releases/download/v0.13.0-beta.1/install.sh &&
sh ~/forchetta-install.sh
    The installer holds the checksum of Forchetta and takes nothing else. Without Node.js 22 it takes one from nodejs.org, checks it, and keeps it only for Forchetta. Then it shows the hooks it adds: answer y, or d to see the whole diff first. If you built Forchetta from the source before, do this first.

  5. Open it, in a new terminal

    forchetta open
    If no window appears, forchetta open --print gives an address for your browser, good once, for two minutes.

What keeps it safe

  • It listens only on your PC, and every request needs a token. The address that opens the page holds a code good once, for two minutes.
  • The window has a profile of its own in Edge or Chrome, without your extensions, which could read your terminals. If it can't have one, forchetta open tells you. The page asks the browser not to translate it nor to check its spelling, which some do on a server.
  • Its data is in a folder only your user can open. On a disk where that isn't possible, Forchetta doesn't start. No telemetry.
  • GitHub builds it from the source, which you can read, and signs which commit it comes from. With the GitHub CLI signed in, the installer checks that too. Each package it uses must match the hash in the repository.

What it can't protect you from: a program that runs as you, in Windows or in WSL, can read your files, those of Forchetta too. And Claude Code in WSL can start programs of Windows, like powershell.exe: the guard doesn't see what they change.

If you find a way around any of this, please tell me in private. More on its security.

What to try

  1. Does the window open by itself?
  2. + new, then session: choose a folder with the button and start it. Do you see its terminal? Can you type in it?
  3. Does Ctrl+V paste in the terminal? If you select text with the mouse, can you paste it in Notepad?
  4. Do Ctrl+K and Ctrl+N work?
  5. In Settings, allow them turns on the notifications. When a session asks for a permission and the window is behind, does one come? Can you answer from the box?
  6. In Ubuntu, does a session started with forchetta run claude show up in the window?
  7. Close the window and run forchetta open again: are the sessions still there?

Good to know

  • Keep your projects in your home of Ubuntu (~/projects). Under /mnt/c they work, but much slower.
  • Leave a terminal of Ubuntu open while the sessions work: Windows may stop WSL after the last one closes.
  • The shortcuts are with Ctrl in place of ⌘.
  • After a restart of Forchetta, open the page again with forchetta open.

To update, run step 4 of this page again: it names the last version.

If you built it from the source before, close your sessions with /exit, then take its hooks away and stop it. After step 4, ~/forchetta and ~/forchetta-node can go, with the history that one kept.

cd ~/forchetta && bin/forchetta hooks uninstall --yes && bin/forchetta daemon stop; cd ~

Say how it went

Also when everything works: it tells me on which Windows. If something doesn't, this command writes a file that helps, and explorer.exe . opens its folder:

forchetta doctor --bundle

Your names of Ubuntu and of Windows, the name of the PC, projects, e-mails and tokens are replaced in it. Look inside before you attach it: an issue on GitHub is public.

Write it on GitHub

Questions and first impressions are welcome in the discussions too.

Remove it

Close your sessions first, with /exit. Then this takes its hooks out of your settings, gives you back your status line, stops it and deletes its folder, with its data:

forchetta hooks uninstall --yes && forchetta daemon stop &&
rm -rf ~/.local/lib/forchetta ~/.local/lib/forchetta-node ~/.local/share/forchetta ~/.local/bin/forchetta

The profile of its window is in Windows: close it, then delete the folder %LOCALAPPDATA%\Forchetta.
