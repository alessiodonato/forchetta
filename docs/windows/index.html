Forchetta on Windows

A beta that needs people to try it.

Version 0.13.0-beta.3, November 2026. Its tests run on Windows Server 2022 and 2025 and on Windows 11 for ARM, in the machines of GitHub, with the real Claude Code and a stand-in for its API. The first reports from a PC are in, from Windows 11.

Forchetta runs on Windows itself: no WSL, no Ubuntu, no administrator. The Claude Code it shows is the one you have, with your account and your settings, and it sees what it sees now: your folders, your programs, the devices connected to the PC. You use Forchetta from a window of Edge or Chrome: the same page as on a Mac.

Do you work inside WSL? There is a guide for that too.

What you need

  • Windows 11, or Windows 10 version 1809 or later, on Intel, AMD or ARM.
  • Claude Code for Windows, with your account. Step 1 installs it.
  • Edge or Chrome. Edge comes with Windows.
  • Git for Windows, if you use git: without it there are no diffs and no worktrees, and the guard doesn't look at git commands.

Node.js is not needed: without it, the installer takes one only for Forchetta.

Install

In PowerShell, opened as usual and not as administrator: type its name in the Start menu.

  1. Claude Code PowerShell

    Skip it if claude --version prints a version. 
    irm https://claude.ai/install.ps1 | iex
    • Open PowerShell again, run claude and log in. Then /exit.

    Done when claude --version prints a version.

  2. Forchetta PowerShell

    irm https://github.com/alessiodonato/forchetta/releases/download/v0.13.0-beta.3/install.ps1 | iex
    • It downloads Forchetta and checks it. Without Node.js 22, or with one in a folder of its version, as winget and nvm may keep it, it takes one from nodejs.org, checks it too, and keeps it only for Forchetta.
    • It lists the hooks it adds to .claude\settings.json and asks Apply the changes? Answer y, or d to see the whole diff first. It keeps a copy of the file.
    • It adds .local\bin, in your user folder, to your PATH: for your user only, where the installer of Claude Code puts its own command.

    Done when it says Ready. Open Forchetta with: forchetta open.

  3. Open it PowerShell, or the Start menu

    forchetta open

    Done when a window shows Forchetta. The sessions open already appear at their next step.

Every day

  • Open it with Forchetta in the Start menu, or forchetta open.
  • Your sessions show up by themselves, wherever you start them: PowerShell, Windows Terminal, Git Bash, VS Code. You can answer their permissions from the box, and the guard keeps them off each other's files.
  • To type into one from Forchetta, start it there: + new in the window, or forchetta run claude in the folder of the project. Closing the window or the terminal leaves it running; /exit ends it. Ctrl-b d leaves it from the terminal.
  • In its terminal, drag to select, CtrlC to copy, CtrlV to paste. The shortcuts are with Ctrl in place of ⌘.

What a Mac has and this has not: the menu bar, the shortcut from any program, and a daemon that starts at login. Here Forchetta starts when you open it.

Update

The command of the install again, in PowerShell and not as administrator. There is nothing to uninstall:

irm https://github.com/alessiodonato/forchetta/releases/download/v0.13.0-beta.3/install.ps1 | iex

It shows what changes in the hooks: answer y. It starts Forchetta again on the new version; then open the window with forchetta open. The sessions at work go on. Forchetta does not look for new versions by itself: this page always has the command of the last one, and the changelog says what it brings.

What keeps it safe

  • It listens only on your PC, and every request needs a token. The address that opens the page holds a code good once, for two minutes.
  • The hooks and the sessions talk to it on pipes of Windows with a name made at random and a key. Each end proves to the other that it has the key before anything passes: a program that takes the place of Forchetta gets nothing, and neither does one that calls it.
  • The window has a profile of its own in Edge or Chrome, without your extensions, which could read your terminals. If it can't have one, forchetta open tells you.
  • Its data is in your user folder, which other users of the PC can't open. No telemetry.
  • The sessions it starts, with + new or forchetta run, get one more MCP server, forchetta, with the tools of the templates of teams. It is given to them when they start, not written in your settings.
  • No program of mine to trust. What runs is Node.js, with the code of Forchetta, which you can read. GitHub builds it from the source and signs which commit it comes from; the installer takes that archive and no other.

What it can't protect you from: a program that runs as you can read your files, those of Forchetta too. And the guard reads the commands of Bash and of PowerShell, not what a script does by itself.

If you find a way around any of this, please tell me in private. More on its security.

What to try

  1. Does the window open by itself, from the Start menu too?
  2. Start claude in a terminal as you always do: does its box come?
  3. + new, then session: choose a folder with the button and start it. Do you see its terminal? Can you type in it, paste with Ctrl+V, and paste in Notepad what you select?
  4. When a session asks for a permission, can you answer from the box? Behind another window, does a notification come? (Settings, allow them.)
  5. Two sessions in one folder: ask the second to change the file the first is changing. Is it stopped? And with a command, in PowerShell?
  6. If Claude talks to devices connected to your PC, does it still reach them, also from a session of + new?
  7. Close the window and open it again: are the sessions still there?

Say how it went

Also when everything works: it tells me on which Windows. If something doesn't, this command writes a file that helps, and explorer . opens its folder:

forchetta doctor --bundle

Your name of Windows, the name of the PC, projects, e-mails and tokens are replaced in it. Look inside before you attach it: an issue on GitHub is public.

Remove it

Close its window and your sessions first, with /exit. Then, in PowerShell, this takes its hooks out of your settings, gives you back your status line, stops it and deletes its folders, with its data:

forchetta hooks uninstall --yes
forchetta daemon stop
cmd /c rmdir "$HOME\.local\lib\forchetta"
Remove-Item -Recurse -Force "$HOME\.local\lib\forchetta-versions", "$HOME\.local\lib\forchetta-node", "$HOME\.local\share\forchetta" -ErrorAction SilentlyContinue
Remove-Item "$HOME\.local\bin\forchetta*", "$([Environment]::GetFolderPath('Programs'))\Forchetta.lnk" -ErrorAction SilentlyContinue

.local\bin stays in your PATH: Claude Code has its command there too.
